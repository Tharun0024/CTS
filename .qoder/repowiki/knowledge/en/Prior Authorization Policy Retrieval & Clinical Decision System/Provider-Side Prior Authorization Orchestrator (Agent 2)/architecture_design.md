The module is organized as a layered Python package centered on `workflow/orchestrator.PriorAuthOrchestrator`, which composes domain services from sibling sub-packages and drives a state-machine lifecycle (`INIT` → `RECEIVED` → `VALIDATING` → `RETRIEVING_EVIDENCE` → `RETRIEVING_POLICY` → `MATCHING_CRITERIA` → `BUILDING_PACKAGE` → `READY_FOR_SUBMISSION` → `SUBMITTED` → `WAITING_FOR_PAYER` → terminal states `APPROVED` / `HUMAN_REVIEW` / `FAILED`). Dependency direction flows inward: `workflow` depends on `retrieval`, `reasoning`, `submission`, `validators`, `database.repositories`, `payer`, `audit`, and `schemas`; cross-cutting concerns are isolated in `audit/audit_logger.py` for per-run transition logging and `config.py` for env-driven settings (NVIDIA/Gemini LLM endpoints, workspace paths, `MAX_RESUBMISSION_ATTEMPTS`). Data access is abstracted through repository classes under `database/repositories/` backed by SQLite (`db_manager.py`) with an `importer.py` for FHIR ingestion. External payer interaction is decoupled behind `payer/agent1_client.Agent1Client`, enabling test injection of mock clients. The `schemas/` package defines Pydantic models (`CanonicalClaim`, `Evidence`, `SubmissionPackage`, `PayerResponse`, `HumanReview`) that serve as the immutable contract between layers. A trust boundary filter (`submission/boundary_filter.py`) enforces minimum-necessary data release before crossing into Agent 1.
