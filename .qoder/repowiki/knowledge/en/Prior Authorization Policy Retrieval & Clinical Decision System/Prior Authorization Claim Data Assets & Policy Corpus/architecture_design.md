Two complementary asset trees under one scope: `DATA-VERSION1/` holds the canonical input dataset (provider `big_patient_data.db`, payer `payer_data.db`, spreadsheets `final_patient_data_PA_IDs_final.xlsx` / `clinical_events_PA_ids.csv` / `prior_authorization_policies.xlsx`, and scenario PDFs SC02–SC07 plus a sample Aetna knee arthroplasty PDF) consumed by the Python pipeline (`pa_pipeline/`) described in its README; `data/` holds downstream artifacts produced or consumed by agents — raw JSONL policy chunks (`raw/ragdata.jsonl`) covering CMS NCDs/LCDs and Aetna CPBs across orthopedics, cardiology, imaging, sleep medicine, oncology, bariatric, neurology, and spine domains; normalized outputs (`normalized/normalized_policies.json`, `processed/chunks.json`); FAISS + BM25 vector index (`vector_store/index.faiss`, `bm25.pkl`, `mapping.json` mapping chunk_id→policy_id); NumPy embeddings (`embeddings/chunk_embeddings.npy`); and a test fixture (`test_claim_aetna_knee.json`). The directory enforces the Provider ↔ Payer trust boundary by keeping provider and payer SQLite databases physically separate, and the vector store serves as the retrieval layer for the RAG agent that evaluates submitted evidence against payer policies.
