- Policy corpus entries in `raw/ragdata.jsonl` follow a fixed schema per line with fields `chunk_id`, `policy_id`, `payer`, `policy_title`, `clinical_domain`, `procedure_codes`, `diagnosis_codes`, `section`, `criterion_id`, `criterion_type`, `criterion_name`, `text`, `text_status`, `policy_last_review_date`, `policy_anticipated_review_date`, `source_reference`, and `policy_status`.
- Chunk IDs encode provenance via prefixes (`CMS-NCD-*`, `CMS-LCD-*`, `AETNA-*`) that directly map to the corresponding policy identifier in `vector_store/mapping.json`, keeping the FAISS index decoupled from policy metadata.
- Evidence items carry a `sensitivity` tag (`ROUTINE`, `PROTECTED_MENTAL_HEALTH`, `PROTECTED_SUBSTANCE_USE`, `PROTECTED_HIV`, `PROTECTED_GENETIC`, `UNKNOWN`) and a `provenance` object linking back to the source record, enforcing the safe sensitivity escrow model documented in the README.
- Provider and payer data are kept in separate SQLite files (`big_patient_data.db` vs `payer_data.db`) with no cross-database queries, preserving the Provider ↔ Payer trust boundary enforced by the ingestion pipeline.
