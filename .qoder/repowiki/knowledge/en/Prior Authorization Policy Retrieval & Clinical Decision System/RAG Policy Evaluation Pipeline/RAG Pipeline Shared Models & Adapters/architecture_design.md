Two cooperating sub-packages form a thin boundary between upstream data sources and the downstream DecisionAgent. `models/rag_models.py` declares the stable Pydantic contracts used across the pipeline: input (`ClaimInput`, `InsurancePrimary`, `DiagnosisInfo`, `ProcedureInfo`), internal chunk representation (`NormalizedChunk`), and output (`ClaimOutput`, `PolicyMatch`, `Criterion`, `DocumentationRequirement`). `adapters/rag_adapter.py` holds pure transformation functions — `build_rag_policy` (aka `generate_rag_policy` / `rag_policy_from_runtime`) converts Version-1 runtime policies into the current RAG policy dict; `rag_claim_adapter` maps a canonical claim to one or more `ClaimInput` dicts (one per procedure) using CPT/Diagnosis lookup tables (`CPT_MAP`, `DIAG_MAP`); `rag_policy_adapter` normalizes RAG `ClaimOutput` back into an Agent-1 policy by resolving criteria via the in-memory `CRITERIA_RULES_REGISTRY`, keyword-based evidence key resolution (`EXPLICIT_EVIDENCE_MAP`, `resolve_evidence_keys`), and safe regex rule parsing (`parse_rule_from_text`). `adapters/runtime_adapter.py` defines the `RuntimeAdapter` class that reads from two SQLite databases under `DATA-VERSION1/` (`big_patient_data.db` for provider data, `payer_data.db` for payer context) and produces the canonical claim shape consumed by `rag_claim_adapter`. It exposes `get_provider_canonical_claim`, `get_provider_evidence_pool`, `attach_payer_context`, `get_linked_runtime_claim`, and `get_payer_context`, with lazy `sqlite3` import to keep the module importable without DB files present. Dependency direction is strictly upward: `runtime_adapter` → canonical claim dict → `rag_adapter` → RAG contract; models are imported by both adapters as the shared schema layer.
