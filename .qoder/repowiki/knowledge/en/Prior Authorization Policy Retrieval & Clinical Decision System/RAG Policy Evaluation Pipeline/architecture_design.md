The pipeline is split into three layers: `rag/` holds the stage-specific components (chunking, embeddings, retrieval with BM25+FAISS candidate pooling, LLM prompt building, evidence building, query building, reranking, aggregation, analysis, normalization, validation) that are composed end-to-end to turn a canonical claim into matched policy criteria; `models/rag_models.py` defines the shared Pydantic schemas (`ClaimInput`, `NormalizedChunk`, `ClaimOutput`, etc.) that all stages consume and produce, acting as the inter-stage contract; `adapters/` provide the boundary layer — `rag_adapter.py` normalizes external provider/payer payloads into `ClaimInput`, converts RAG outputs back into the Agent-1 policy format using a fixed `CRITERIA_RULES_REGISTRY` and keyword-based evidence key resolution, and `runtime_adapter.py` wires the runtime invocation. Stages communicate exclusively through the typed models in `models/`, keeping each component pluggable while preserving a single data contract across chunking → retrieval → LLM → evidence → validation.
