The workspace is organized as a layered Python application where `services_and_transformation` (integrated pipeline) orchestrates the full claim adjudication loop by composing the `rag_pipeline` (BM25/FAISS retrieval with policy consistency gate), the `decision_engine` (deterministic clinical eligibility with optional LLM criterion assessment), and the `agent2_orchestrator` (provider-side submission/resubmission flow). Cross-cutting contracts are shared through `models/rag_models.py`, `transformation/canonical_claim.py`, and `adapters/` so that each child reads/writes CanonicalClaim and ClaimInput/ClaimOutput objects rather than calling each other directly. Static inputs live in `data_assets/` (raw datasets, preprocessed claims, FAISS index, scenario PDFs) and are consumed by both `scripts/` (build/benchmark/evaluate/query) and the runtime services. The `api/` FastAPI layer exposes the integrated pipeline as HTTP endpoints, while `tests/` validates all layers and `reports/` stores V1 verification artifacts. Configuration for embedding models, rerankers, device placement, and LLM providers is centralized in `config/config.yaml` and environment variables defined in `.env.example`.
