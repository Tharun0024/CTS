Two cooperating sub-packages form the service layer above adapters and decision modules. `transformation/canonical_claim.py` normalizes heterogeneous runtime claim shapes into a single canonical contract (`claim_id`, `submission`, `case_data` with `clinical_metrics`, `evidence`) by flattening `clinical_information`/`treatment_history`/`diagnostic_information` sections and `documents` into standardized evidence items. `services/integrated_pipeline.py` exposes three entry points: `run_integrated_pipeline` (canonical claim → RAG pipeline via injected `components` dict → `DecisionResponse`), `run_pipeline_from_db` (provider+payer DB lookup via `RuntimeAdapter` then delegates to the integrated pipeline), and `run_agent2_v1_pipeline` / `run_agent2_pipeline_from_db` which wrap the first in an immutable versioned loop (V1→V2…) that invokes Agent 2's `RejectionAnalyzer`, selects minimal provider-side evidence via `_select_recovered_evidence`, enforces a sensitivity release gate (`ROUTINE` only), builds a deep-copied next claim version with append-only `new_evidence_delta`, and re-runs Agent 1 until terminal or `MAX_RESUBMISSION_ATTEMPTS` is reached. Dependency direction is strictly inward: this module depends on `adapters.*`, `rag.*`, `decision.agent`, `models.rag_models`, and optionally `agent2.*`; nothing inside the package is imported back by those layers. The `components` dict is the explicit boundary for plugging in query builders, embedders, retrievers, analyzers, LLM clients, and validators.
