The module is organized around a layered pipeline exposed via `DecisionAgent` in `agent.py`, which orchestrates two evaluation phases: (1) an optional LLM-assisted criterion assessment phase that queries pluggable providers (`NVIDIAProvider`, `OpenRouterProvider`, `GeminiProvider` in `llm_provider.py`) to produce constrained `CriterionAssessment` objects describing whether each policy criterion's required evidence is SUPPORTED/MISSING/UNCERTAIN/CONFLICTING; and (2) a deterministic decision compiler in `decision_logic.py` that applies the fixed hierarchy EXCLUSION → CONFLICT → FAILED → MISSING → APPROVE, falling back to HUMAN_REVIEW on any error. The LLM layer is intentionally non-decisional — its outputs are translated into conservative synthetic evidence or missing-requirement signals via `_translate_assessments_to_deterministic_inputs` so the final outcome is always computed by `make_decision`. Core submodules: `policy_evaluator.py` provides rule validation, field resolution, operator evaluation, and exclusion/clinical-rule checks; `evidence_evaluator.py` groups evidence by key and computes per-key status using a severity-weighted scheme; `schemas.py` defines all Pydantic models (Policy, CaseData, EvidenceItem, Rule, etc.) as the single source of truth; `llm_prompt.py` holds system/user prompt templates and builders; `llm_schemas.py` defines LLM-specific response contracts; and `__init__.py` re-exports the public surface. Dependency direction flows inward: agent → decision_logic → {policy_evaluator, evidence_evaluator}, with schemas and llm_* modules consumed at every layer but never depending upward.
